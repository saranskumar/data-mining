> Team: Saran S Kumar (453) · S J Advyaith (460) · Nadheem K Sultan (440)

---

## What this project does

| Layer | Method | Purpose |
|-------|--------|---------|
| Forensic | Feature engineering (noise, FFT/DCT, colour, GLCM) → PCA → DT / MLP | Detect AI-generated images |
| Watermark | Learned CNN encoder/decoder (PyTorch, HiDDeN-style) | Embed + verify invisible provenance mark |
| Hybrid | Rule-based fusion of both layers | Combined verdict with explainability |

Dataset: [CIFAKE](https://www.kaggle.com/datasets/birdy654/cifake-real-and-ai-generated-synthetic-images) (100 k train / 20 k test, 32×32, REAL vs FAKE generated by Stable Diffusion 1.4).

## Hardware notes

- **CPU** (Track A): feature extraction is multiprocessed; full 100 k images ~45–90 min depending on CPU. Use `--subset 5000` for dev.
- **GPU** (Track B): RTX 2050 4 GB. AMP enabled. Batch size 128 at 32×32 fits comfortably. Expect ~10–20 min / epoch.
- **Watermark fallback**: if val bit-accuracy < 0.85, reduce `watermark.message_bits` in `configs/config.yaml` (ladder: 48 → 32 → 24 → 16).

## Key design decisions

- **No test-set leakage**: `StandardScaler` and `PCA` fit exclusively on train rows.
- **sklearn MLP** (not PyTorch) for forensic classifier — keeps forensic pipeline CPU-only and scikit-learn clean.
- **Rule-based fusion** — explainable, no extra training data.
- **GLCM at 64 levels** — reduces sparsity on 32×32 images vs 256 levels.
- All numbers in the report are produced by scripts; nothing is hand-typed.

See `docs/decisions.md` for full rationale.
